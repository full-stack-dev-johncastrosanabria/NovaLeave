7. FLUJO DE LOGIN (ejemplo con PowerShell)
================================================================================

$session = New-Object Microsoft.Powershell.Commands.WebRequestSession

# 1. Obtener página de login y token antiforgery
$response = Invoke-WebRequest -Uri 'http://localhost:51293/Identity/Account/Login' -UseBasicParsing -WebSession $session
$token = ($response.Content -match 'name="__RequestVerificationToken" type="hidden" value="([^"]+)"') ? $matches[1] : ""

# 2. Hacer login
$loginData = @{
    'Input.Email' = 'user@demo'
    'Input.Password' = 'Demo123!'
    'Input.RememberMe' = 'false'
    '__RequestVerificationToken' = $token
}

$response = Invoke-WebRequest -Uri 'http://localhost:51293/Identity/Account/Login' -Method POST -Body $loginData -UseBasicParsing -WebSession $session -MaximumRedirection 0

# 3. Verificar redirección a /mis-solicitudes (para User)
#    Redirecciones por rol:
#    - User      → /mis-solicitudes
#    - Approver  → /aprobaciones

10. SOLUCIÓN DE PROBLEMAS COMUNES
================================================================================

# Error: "address already in use" en puerto 51292 o 51293
# Solución: Matar procesos en esos puertos
powershell -Command "Get-NetTCPConnection -LocalPort 51292,51293 -ErrorAction SilentlyContinue | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }"

# Error: Base de datos no accesible
# Verificar: docker ps (contenedor novaleave-sqlserver debe estar "healthy")
# Verificar: puerto 1433 mapeado en docker-compose.yml

# Error: Migraciones no se aplican
# Verificar: ConnectionString en appsettings.json coincide con docker-compose.yml
# Ejecutar: dotnet ef database update --verbose (para ver detalles)

# Resetear todo (BD + migraciones + seeds):
docker compose down -v
docker compose up -d
dotnet ef database update --project src/NovaLeave.Infrastructure --startup-project src/NovaLeave.Web
dotnet run --project src/NovaLeave.Web/NovaLeave.Web.csproj

12. ENDPOINTS PRINCIPALES PARA PROBAR
================================================================================

# Públicos:
GET  /health/live              → Health check
GET  /health/ready             → Readiness check (con BD)
GET  /Identity/Account/Login   → Página de login
POST /Identity/Account/Login   → Login (requiere token antiforgery)

# Usuario (requiere login + rol User):
GET  /mis-solicitudes          → Mis solicitudes de vacaciones
GET  /mis-solicitudes/crear    → Crear nueva solicitud

# Aprobador (requiere login + rol Approver):
GET  /aprobaciones             → Solicitudes pendientes de aprobar

# HR (requiere login + rol HR):
GET  /rrhh                     → Panel de RRHH
GET  /rrhh/usuarios            → Gestión de usuarios
GET  /rrhh/balances            → Gestión de balances
