# DR-002 — Generated-Artifact Review Rule

**Status**: Accepted
**Date**: 2026-07-29
**Deciders**: Principal-architect review (2026-07-29), accepted by the repository owner
**Related**: `tasks/` derived execution view; `tasks/coverage-report.md`; `AUDIT_REPORT.md` §19; constitution §16.2 (PR checklist)

## Context

Two consecutive verification artifacts in this repository certified content that failed direct
inspection:

1. `AUDIT_REPORT.md` §19 declared "no unsubstantiated claims" while three documents claimed
   accrual behavior was "Implemented in `BalanceService…`" in a repository with zero code
   (fixed 2026-07-28).
2. `tasks/coverage-report.md` certified "COVERAGE: 100%" over 153 generated TASK files, **all
   153 of which** contained unexpanded PowerShell interpolation artifacts
   (`$(@{…}.OfficialId)`) in their Description, Context, Scope, Acceptance Criteria, and
   Technical Notes sections, plus a UTF-8 BOM (repaired 2026-07-29).

In both cases the artifact was produced and certified by tooling without a human opening the
output. During the 2026-07-29 repair, the same failure class recurred a third time in miniature:
an automated fix of `tasks/BACKLOG.md` mangled its Epics section because a second blob shape
(`.Slug`) was not anticipated — caught only because the output was manually sampled before
committing. The lesson is systemic, not personal.

## Decision

For every pull request that adds or regenerates machine-generated artifacts (task trees,
coverage or audit reports, generated documentation, diagrams, or prompts):

1. **Human sampling is mandatory before merge**: open and read at least **five randomly chosen
   generated files** (or all of them when fewer than five exist), end to end.
2. **Self-certification is insufficient**: a report generated by the same tool family it
   certifies (e.g., a coverage report emitted by the generator) does not count as verification.
   At least one check must be independent of the generator — a human read, or a validator built
   separately from the generator.
3. **Mechanical invariants must be asserted**: generated Markdown must be free of template
   artifacts (`$(`, `{{`, unexpanded placeholders), free of BOM, and must round-trip its source
   identifiers (e.g., every `TASK-nnn` maps to an existing canonical `Tnnn`).
4. **The PR description must state** what was sampled and what the independent check was.

## Consequences

- Applies from 2026-07-29 onward to all branches. It supplements — does not replace — the
  constitution §16.2 pull-request checklist.
- Regeneration of the `tasks/` tree must re-run the invariant checks in item 3 (a validation
  script fulfilling this exists in the repair-session history and can be committed under
  `tools/` once a code tree exists).
